# FastAPI Logging and Ollama Demo

This project is a small FastAPI service built and managed with [uv](https://docs.astral.sh/uv/).
It includes configurable console/file logging, Pydantic request validation, automated tests,
a Postman collection, Ollama-powered text generation, and a Docker image.

## Project structure

```text
src/app/main.py             FastAPI endpoints
src/app/logging_config.py   Application logging configuration
src/app/ollama.py           Ollama client
src/app/database.py         PostgreSQL connection helper
src/app/redis_store.py      Redis cache and request history
tests/                      API and logging tests
postman/                    Postman collection
docker/                     Dockerfile and Docker ignore rules
```

## Local setup

```powershell
uv sync
uv run pytest
$env:OLLAMA_MODEL="qwen2.5:1.5b"
uv run uvicorn app.main:app --app-dir src --reload
```

The API is available at `http://localhost:8000`; Swagger UI is at
`http://localhost:8000/docs`. Logs are written to `logs/app.log` and stdout.
Set `LOG_LEVEL` (`DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL`) and `LOG_FILE`
to customize logging.

## Logging

`src/app/logging_config.py` configures the application root logger with:

- `INFO` as the default level, configurable through `LOG_LEVEL`
- Timestamped output using `timestamp | level | logger | message`
- Console output to stdout
- Rotating file output to `logs/app.log`
- A 1 MB maximum file size and 3 backup files

Logging was developed incrementally in three separate commits:

```text
621e7fc feat(logging): add basic application logging
08ed41b feat(logging): add levels and structured formatting
1d383e2 feat(logging): add rotating file output and validation
```

Validate logging directly:

```powershell
uv run python -c "import logging; from app.logging_config import configure_logging; configure_logging(level='INFO', log_file='logs/validation.log'); logging.getLogger('validation').info('logging validation passed')"
Get-Content logs\validation.log -Tail 1
```

## API validation

Import `postman/fastapi-logging-demo.postman_collection.json` into Postman and run:

| Request | Expected result |
| --- | --- |
| `GET /health` | `200 {"status":"ok"}` |
| `GET /db/health` | `200` when PostgreSQL accepts `SELECT 1` |
| `GET /requests/recent` | Recent generation requests stored in Redis |
| `POST /items` with `{"name":"Notebook","quantity":2}` | `201` with generated `id` |
| `POST /items` with `{"name":"","quantity":0}` | `422` validation response |
| `POST /generate` with `{"prompt":"Say hello"}` | `200` generated by the configured Ollama model |

The same requests can be run from Swagger UI.

## PostgreSQL

The application reads `DATABASE_URL` and defaults to the PostgreSQL container
configuration from this project:

```text
postgresql://omar:123456@localhost:8000/mydatabase
```

Because the PostgreSQL container maps host port `8000` to container port `5432`,
run the FastAPI application on another host port:

```powershell
$env:DATABASE_URL="postgresql://omar:123456@localhost:8000/mydatabase"
uv run uvicorn app.main:app --app-dir src --port 8001
```

Then open `http://127.0.0.1:8001/docs` and execute `GET /db/health`.
For a conventional setup, recreate PostgreSQL with `-p 5432:5432` and use
`postgresql://omar:123456@localhost:5432/mydatabase`.

The database integration was verified against the running container:

```text
DATABASE_CONNECTED=True
("mydatabase", "omar")
GET /db/health -> {"status":"ok","database":"postgresql"}
```

The original `postgres:latest` container exited because its existing volume used
the pre-PostgreSQL-18 data layout. The `pgdata` volume was preserved, and the
container was recreated with `postgres:17`, which started successfully.

## Ollama generation

Install and start Ollama, then download a Qwen 2.5 1.5B model:

```powershell
ollama pull qwen2.5:1.5b
ollama serve
```

The `POST /generate` endpoint calls Ollama's `/api/generate` API. It defaults to
`http://localhost:11434` and `qwen2.5:1.5`; override them with `OLLAMA_BASE_URL`
and `OLLAMA_MODEL`. When running the API in Docker Desktop on Windows, use
`OLLAMA_BASE_URL=http://host.docker.internal:11434`.

Every successful generation is stored in PostgreSQL in the `generations` table
with its prompt, model, response, and creation timestamp. The table is created
automatically when the API starts.

## Redis cache and request history

The API uses Redis at `redis://localhost:6379/0` by default. Override it with
`REDIS_URL`. Successful `/generate` responses are cached for one hour using a
model-and-prompt key. Every generation request, including cache hits, is stored
in a Redis list with its prompt, response, model, cache status, and timestamp.

With the Redis container running:

```powershell
docker exec -it my-redis redis-cli
GET api:generate:<cache-key>
LRANGE api:request-history 0 -1
```

Or use the API:

```powershell
curl.exe "http://127.0.0.1:8001/requests/recent?limit=20"
```

Query stored generations:

```powershell
$env:DATABASE_URL="postgresql://omar:123456@localhost:8000/mydatabase"
uv run python -c "import os, psycopg; conn=psycopg.connect(os.environ['DATABASE_URL']); print(conn.execute('SELECT id, prompt, model, response, created_at FROM generations ORDER BY id DESC').fetchall())"
```

The exact model tag available on the validation machine is `qwen2.5:1.5b`, so set
`OLLAMA_MODEL=qwen2.5:1.5b` when using that local installation.

## Docker deployment

Generate the lockfile, build, and run:

```powershell
uv lock
docker build -f docker/Dockerfile -t fastapi-logging-demo .
docker run --name fastapi-logging-demo -p 8001:8000 `
  -e DATABASE_URL="postgresql://omar:123456@host.docker.internal:8000/mydatabase" `
  -e REDIS_URL="redis://host.docker.internal:6379/0" `
  -e OLLAMA_BASE_URL="http://host.docker.internal:11434" `
  -e OLLAMA_MODEL="qwen2.5:1.5b" fastapi-logging-demo
curl.exe http://localhost:8001/health
curl.exe http://localhost:8001/db/health
curl.exe "http://localhost:8001/requests/recent?limit=20"
docker stop fastapi-logging-demo
docker rm fastapi-logging-demo
```

The Dockerfile uses a non-development uv environment, listens on all interfaces,
and supplies Docker Desktop host-gateway defaults for PostgreSQL, Redis, and Ollama.
Port `8001` is used because PostgreSQL is mapped to host port `8000`.
For a reproducible build, commit the generated `uv.lock` file.
